A SIMPLE START

صرف تین آسان قدم۔

اسی لیپ ٹاپ پر ترجمہ آزمانے کا طریقہ۔

1

ایئربڈز کنیکٹ کریں

Windows سے اپنے AirPads / AirPods کنیکٹ کریں۔ پھر لائیو ترجمے میں «ڈیوائسز تازہ کریں» دبائیں۔ سننے کی ڈیوائس میں Headphones منتخب ہونا چاہیے۔

2

سمت منتخب کرکے Start دبائیں

اردو → English منتخب کریں اور کہیں: «میرا نام بلال ہے۔ آپ کے پروجیکٹ پر سات دن لگیں گے اور قیمت پانچ سو ڈالر ہوگی۔» ترجمہ چھوٹے معنوی حصوں میں سنائی دے گا؛ کچھ تاخیر لازمی ہے۔

3

آواز سنیں، متن چیک کریں

آواز صاف ہے؟ قیمت، دن اور نام درست آئے؟ دوسری سمت آزمانے کے لیے Stop دبائیں، English → اردو منتخب کریں، پھر Start دبائیں۔ ختم کرنے پر Stop ضرور دبائیں۔

آواز نہ آئے یا HTTP 429 ہو تو؟

آواز کا خانہ فعال اور Headphones منتخب رکھیں۔ HTTP 429 کا مطلب API کی رفتار یا استعمال کی حد ہے؛ اسکرین پر بتایا گیا انتظار کریں۔ بار بار Start نہ دبائیں۔ paid سروس خودکار فعال نہیں ہوتی۔

Zoom اور Google Meet کے ساتھ کیسے جڑے گا؟

موجودہ ورژن میں meeting audio routing ابھی شامل نہیں۔ اگلے مرحلے میں دو الگ آڈیو راستے بنیں گے:

آپ کی آواز: مائیک → ایپ → انگریزی آواز → virtual microphone → Zoom / Meet۔

کلائنٹ کی آواز: Zoom / Meet → الگ virtual audio راستہ → ایپ → اردو آواز → ایئربڈز۔

Zoom کے Audio یا Meet کے Settings → Audio میں ان راستوں کو microphone اور speaker منتخب کریں گے۔ یہ ہمارے منتخب آڈیو روٹنگ طریقے میں Zoom/Meet API یا کلائنٹ کے لیے الگ app کے بغیر ہوگا۔ پہلی ترتیب کے بعد devices دوبارہ منتخب یا واپس عام مائیک/ہیڈفون پر کر سکتے ہیں۔ موجودہ app میں دونوں سمتوں کو بیک وقت چلانا، feedback سے بچاؤ اور اصل remote test باقی ہیں۔ driver نصب کرنے یا Windows audio settings بدلنے سے پہلے اجازت لی جائے گی۔

پرائیویسی اور API key

API key اسی project کی .env فائل میں رہتی ہے؛ اس ونڈو سے نظر نہیں آتی۔ Start پر منتخب مائیک کی آواز Google کو ترجمے کے لیے بھیجی جاتی ہے، اور ترجمے کا متن Google کو آواز بنانے کے لیے۔ مقامی ہسٹری یا آڈیو فائل محفوظ نہیں ہوتی۔ Google کی اپنی ڈیٹا پالیسی الگ لاگو ہوتی ہے۔ قدرتی آواز، ترجمے کی مکمل صحت یا ہر غلطی معلوم ہونے کی ضمانت نہیں۔
